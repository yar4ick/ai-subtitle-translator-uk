# План: ai-subtitle-translator-uk

ШІ-переклад субтитрів (SRT) з англійської на українську.
CLI-команда: `aisubs`.

## Цілі

- **Ощадливість токенів**: модель бачить лише текст реплік, без таймкодів і розмітки.
- **Відтворюваність**: усе, що можна зробити кодом, робить детермінований код; ШІ лише складає глосарій і перекладає. Модель у підписочних CLI недетермінована (температурою не керуємо), тому кожен прийнятий переклад зберігається як артефакт і повторно не генерується.
- **Незалежність від ШІ-постачальника**: працює з будь-яким агентом, що вміє запускати команди (Claude Code, Codex CLI, Gemini CLI тощо), і в ручному режимі через веб-чат.
- **Пріоритетна платформа для оптимізації та вимірів**: Claude Code (підписка Pro).

## Архітектура

Ядро — Python CLI **без залежностей** (лише stdlib, Python ≥ 3.10). Ручний режим `next`/`import` — це і є ядро; усі агентні сценарії — обгортки над ним.

Інструкції для агента **видає сам CLI**: `aisubs guide film.srt`. Файл `AGENTS.md` у репозиторії інструмента агент не побачить, бо працює в папці з фільмом. Тому користувач будь-якого агента пише одну фразу: «виконай `aisubs guide film.srt` і дій за інструкцією».

| Користувач | Як працює |
|---|---|
| Claude Pro/Max | Плагін Claude Code: `/plugin marketplace add yar4ick/ai-subtitle-translator-uk`, `/plugin install aisubs@aisubs`, далі `/aisubs:translate film.srt`. Скіл викликає `aisubs` з папки плагіна (тому лише stdlib — нічого не треба встановлювати) і дотримується `aisubs guide` |
| ChatGPT (Codex CLI), Gemini CLI, інші агенти | `pipx install git+https://github.com/yar4ick/ai-subtitle-translator-uk`, далі фраза «виконай `aisubs guide film.srt`…» |
| Тільки веб-чат | `aisubs next` друкує готовий до вставки промпт, `aisubs import` приймає вставлену відповідь |
| API-ключ (пізніше) | `--backend anthropic/openai`, необов'язково |

Запуск — у папці з фільмом.

### Робоча папка перекладу

Поруч із фільмом створюється `film.aisubs/`:

- `meta.json` — назва фільму, хеш вихідного SRT, версія промпту, налаштування;
- `cues.json` — репліки з таймкодами, знятими тегами, SDH-метаданими;
- `candidates.json` — імена/мітки мовців, знайдені кодом;
- `glossary.json` — персонажі, стосунки, терміни, опис сюжету (редагується вручну);
- `chunks/` — частини для перекладу (по сценах);
- `done/` — прийняті переклади разом із хешем вихідного SRT, моделлю, версією промпту та статусом (`ok` / `refused` / `partial`); повторно не перекладаються.

Це дає змогу продовжити після ліміту підписки або змінити ШІ посеред фільму.

## Пайплайн

| Етап | Хто | Що |
|---|---|---|
| 1. Розбір SRT | код | таймкоди, стилі, «сміття» прибирає код |
| 2. Теги | код | теги навколо всієї репліки (`<i>…</i>`, `{\an8}` на початку) знімаються й повертаються кодом; плейсхолдер лише для тегу посеред репліки |
| 3. SDH | код | мітки мовців (`SOPHIE:`) спершу зберігаються як метадані; далі за замовчуванням SDH прибирається з тексту (порожні після цього репліки видаляються, `- [laughs] / - Hi` стає звичайною реплікою); `--keep-sdh` зберігає й перекладає SDH |
| 4. Сцени й частини | код | межі по паузах у таймкодах; частина = кілька цілих сцен (~150–250 реплік) |
| 5. Кандидати | код | імена, мітки мовців, звертання + 2–3 приклади |
| 6. Глосарій | ШІ, один раз | персонажі, стосунки, ти/ви, терміни, сюжет у 2–3 реченнях; за потреби — веб-пошук про фільм (див. «Інформація про фільм») |
| 7. Переклад | ШІ | строге 1:1, формат обміну нижче |
| 8. Перевірка | код | див. «Перевірки» |
| 9. Повторний переклад | ШІ | лише рядки, що не пройшли перевірку |
| 10. Збирання `.uk.srt` | код | оригінальні таймкоди, перенесення рядків, типографіка |

## Формат обміну з моделлю

Вхід (одна репліка — один рядок):

```
12|Ж|Where were you last night?
13|Ч|I was at the guest house.
14a|-Who's that?
14b|-Nobody.
```

- Номери — короткі, у межах частини, без дірок.
- Друге поле (стать мовця) — лише якщо відома з SDH-мітки або глосарію.
- Репліка з діалогом `- A / - B` ділиться на `14a`/`14b`; збирається назад кодом.
- Перенесення рядків усередині репліки прибираються; переносить `assemble`.

Вихід:

```
12|Де ти була вчора ввечері?
13?|Я був у гостьовому будиночку.
```

- `?` **після номера** — модель не впевнена в роді/числі/ти-ви. Знак питання в тексті на це не впливає.
- Строге 1:1: кожна репліка перекладається окремо, сусідні не зливаються, слова між репліками не переносяться. Промпт пояснює це прямо (англійська й українська мають різний порядок слів — модель має перебудувати фразу в межах репліки).
- Розбір — за першим `|`.

**Толерантний `import`**: приймає відповідь у code fence, з зайвим текстом до/після, у вигляді таблиці; ігнорує коментарі. `next` повторно видає лише пропущені номери.

**Контекст між частинами**: оскільки частини ріжуться по сценах, достатньо 5 останніх реплік попередньої частини (оригінал + переклад) і 2–3 наступних (лише оригінал), а також «стан»: рішення про ти/ви та нові імена, що з'явилися в попередніх частинах.

## Рід, число і ти/ви

В українській від контексту залежать:

- **рід мовця**: «я зробив / зробила»;
- **рід адресата**: «ти зробив / зробила», кличний відмінок;
- **число адресатів**: you → ти / ви (множина);
- **ти / ви ввічливе** — властивість **пари** персонажів, і вона може змінюватися протягом фільму.

`glossary.json` зберігає:

- персонажів: ім'я (оригінал → українською), стать, роль;
- стосунки: пари персонажів, ти/ви, з якої сцени діє (якщо змінюється);
- терміни;
- опис сюжету в 2–3 реченнях;
- для кожного запису — джерело: `user` / `sdh` / `web` / `wikipedia` / `inferred`, а для персонажів ще й прапорець, чи знайдене ім'я в субтитрах.

Пріоритет джерел: `user` > `sdh` > `web` / `wikipedia` > `inferred`.

Хто говорить конкретну репліку, глосарій не каже — це виводиться з контексту сцени. Джерела, від найнадійніших:

| Джерело | Приклад | Хто аналізує |
|---|---|---|
| Мітки мовців (SDH) | `SOPHIE: Where are you?`, `[Ethan]` | код → метадані |
| Звертання за ім'ям | `Thanks, Sophie.` | код знаходить, ШІ робить висновок |
| Слова, що вказують на стать | `I'm a good wife`, `Mr./Mrs.`, `he said` | ШІ |
| Тире в репліці | `- A / - B` — два мовці в одній репліці (лише всередині репліки) | код |
| Знання про фільм | назва й рік фільму | ШІ, з перевіркою |
| Веб-пошук / Wikipedia | список персонажів і акторів | ШІ або код, з перевіркою кодом |
| Список персонажів від користувача | `Ethan — ч, Sophie — ж, ти` | найнадійніше |

Назву й рік фільму `prepare` пропонує з імені файлу; користувач підтверджує або задає `--title`. README радить: для SDH-субтитрів результат кращий, а для маловідомих фільмів варто вручну перевірити глосарій.

### Інформація про фільм

Список персонажів зі статтю, ролями і стосунками («Ітан — чоловік Софі») закриває більшість питань про рід і ти/ви. Він не каже, хто говорить конкретну репліку, але дає моделі надійні факти для висновків із контексту сцени.

1. **Знання моделі.** Спершу агент використовує те, що модель знає про фільм.
2. **Веб-пошук через агента** (необов'язковий; у `aisubs guide` — умовний крок «якщо маєш веб-пошук…»): лише якщо знань моделі недостатньо. Один запит «назва + рік + cast/characters», з результату — лише ім'я, стать, роль, стосунки. Повні сторінки не відкривати.
3. **Wikipedia через код** (необов'язковий, `aisubs prepare --wikipedia`): CLI сам завантажує розділ «Cast» зі статті про фільм через MediaWiki API (без ключа, `urllib` зі stdlib). Повністю детерміновано і без токенів на пошук, але розбір сторінок крихкий — тому лише як опція, з тестами на кількох статтях; без мережі або при невдалому розборі просто пропускається.
4. **Перевірка кодом.** Персонажі з пошуку чи Wikipedia, чиїх імен немає в `candidates.json`, позначаються як неперевірені. Якщо майже ніхто не збігся, найімовірніше, знайдено не той фільм — `validate` попереджає.

При сумніві модель ставить `?` після номера і може обирати родово-нейтральну конструкцію, якщо це природно. 100% точності без звуку не буде; мета — не вгадувати мовчки, а позначати сумнівні місця.

## Перевірки (`validate`)

Дешеві перевірки кодом:

- усі номери на місці, немає порожніх і злитих реплік;
- плейсхолдери збережені;
- репліка не лишилася англійською (лише латиниця);
- немає російських літер (ы э ъ ё);
- імена написані так, як у глосарії;
- типографіка: лапки «», один символ …;
- позначки `?`;
- частина зі статусом `refused` (модель відмовилася перекладати — актуально для насильства, лайки тощо).

Норми — **Netflix Ukrainian Timed Text Style Guide**, як орієнтир, а не догма:

- 42 символи в рядку, максимум 2 рядки;
- 17 CPS: понад 17 — попередження в звіті; понад 20 або понад 2 рядки — одна повторна спроба, далі лише попередження (часто й оригінал перевищує 17 CPS);
- діалог: дефіс без пробілу (`-Текст`), один мовець на рядок;
- числа 1–10 словами;
- правила перенесення (не розривати словосполучення, не лишати 1–2 слова у верхньому рядку) — реалізуються в `assemble`.

## SRT: кодування й «сміття»

- Кодування: `utf-8-sig` → UTF-16 з BOM → cp1252; ручне `--encoding`. Вихід — UTF-8 (опція BOM для старих плеєрів).
- Вивід CLI у консоль — завжди UTF-8 (інакше Windows-консоль із cp1252 впаде на кирилиці).
- Толерантність до: збитих номерів, `.` замість `,` у таймкодах, `<font>`, HTML-сутностей, рекламних реплік («Subtitles by…»), перекриття таймкодів.
- Пісні (`♪`): за замовчуванням перекладаються як звичайні репліки (часто сюжетні); опція залишати оригінал.
- Мова оригіналу у v0.1 — лише англійська (евристики пошуку імен, SDH, Mr/Mrs розраховані на неї).

## Економія токенів

**Вхід**
- Лише `n|текст` з короткою нумерацією в межах частини; теги навколо всієї репліки знімає код.
- Код відкидає репліки без перекладу: порожні, цифри, суто музичні позначки.
- Для глосарію — вибірка кандидатів, не весь фільм (весь фільм — ~12–20 тис. вхідних токенів і все одно пропускає персонажів, що з'являються пізніше).
- Плейсхолдери: порівняти `⟦1⟧` з `<i>…</i>` чи `[[1]]` за вартістю в токенах і надійністю на етапі виміру.

**Вихід**
- Лише `n|переклад`, без повторення оригіналу та пояснень. Українська займає помітно більше токенів, ніж англійська, тож вихід, імовірно, головна стаття витрат.

**Робота агента**
- Одна частина — один цикл: `aisubs next` → агент пише відповідь у файл → `aisubs import`. Агент нічого не досліджує сам.
- Субагент на частину платить фіксовану ціну за системний промпт і не має перекладу попередньої частини, тому частини йдуть послідовно. Що дешевше — одна сесія чи субагенти — вирішується вимірами, а не припущенням.
- Для перекладу, імовірно, достатньо Sonnet — перевірити вимірами.

**Без повторних витрат**
- Прийняті частини в `done/` не перекладаються повторно.
- Повторно перекладаються лише рядки, що не пройшли перевірку.
- Перевірка якості — лише для позначених реплік.

## Етапи

Спершу мінімальний наскрізний варіант і реальний фільм, бо формат, розмір частин, контекст і вибір моделі — гіпотези, на яких будується решта.

Кожен етап — окрема гілка, коміти, злиття в `main`.

0. ~~**Ініціалізація**~~: репозиторій, LICENSE (MIT), `.gitignore`, план, README-заглушка.
1. **SRT**: читання/запис, кодування, «сміття» на рівні формату (нумерація, таймкоди, порожні рядки), тести «прочитав → записав без змін» (`unittest` зі stdlib), CI на Linux і Windows. «Сміття» всередині тексту (`<font>`, HTML-сутності, реклама) — етап 2; відкриті субтитри Blender у тестах — етап 2, після перевірки ліцензії.
2. **Мінімальний наскрізний варіант**: `prepare` (частини по сценах, теги, «сміття» в тексті, SDH, діалоги `a`/`b`), `status`, `next` (з `--brief` без інструкцій — для агента, що вже їх має), толерантний `import`, `assemble` з перенесенням рядків і типографікою. Мінімальний промпт перекладу. Тестовий зразок — субтитри Sintel (CC BY 3.0).
3. **Реальний фільм** (локально): переклад через Claude Code і через веб-чат; виміри токенів; вибір розміру частин, обсягу контексту, формату плейсхолдерів, моделі, режиму (сесія чи субагенти).
   Порівняння з людським перекладом: 2–3 пари EN/UK субтитрів з OpenSubtitles у `eval/` (лише локально, у `.gitignore`). `tools/compare.py` зіставляє субтитри за часом (автоматично визначає зсув і частоту кадрів), рахує довжину й CPS, шукає кандидатів на розбіжності в роді/числі та ти/ви, порівнює імена, дає випадкову вибірку. Еталон — орієнтир, а не істина: розбіжності оцінює автор.

   **Результати (Sonnet, з пробілами в CPS):**

   | | v1 | v2 крок 1 (ліміти + приклади) | Еталон |
   |---|---|---|---|
   | Stranger Things, ч. 1: > 20 CPS | 21,6% | **0%** | 1,9% |
   | Stranger Things, ч. 1: символи від EN | 91% | 72% | 80% |
   | Cyberpunk: > 17 CPS | 8,6% | **0,4%** | 0,7% |
   | Cyberpunk: символи від EN | 90% | 82% | 88% |

   - Тісні рядки (`≤N`) дотримують ліміту в 99% випадків; зміст на вибірці збережений, мова живіша.
   - Без глосарія лишаються помилки роду (мати говорить чоловічим родом) і ти/ви, які змінюються протягом фільму (Leon: Матильда спершу на «ви» до Леона).
   - Позначка `?` як страховка не працює: модель ставить її рідко й не на помилкових рядках.
   - Один агент на фільм з `import --next` дешевший за агента на частину (Cyberpunk, 2 частини: ~52 тис. проти ~80 тис. за метрикою агента; точна витрата ліміту підписки ще не виміряна).
   - **Крок 2, глосарій** (`aisubs glossary`, `glossary.txt`): виправив помилки роду в Stranger Things (репліки матері) і кальки («Файербол» → «Вогняна куля»); у Cyberpunk не допоміг — факти про персонажів модель має, але неправильно визначає, хто говорить. У Leon модель обрала Матильда→Леон «ти», людина — «ви»: це рішення варто дати перевірити користувачеві.
   - **Крок 3, `ID|S>A|переклад`**: модель явно називає мовця й адресата, і переклад узгоджений з її вибором (перевірка роду кодом: 0 конфліктів). Але в Cyberpunk вона переплутала чергування реплік у сцені (підказка «my night shift» → мати), і помилки роду лишилися — тепер уже видимі в `S>A`. Довжина тримається: > 20 CPS — 0% в обох фільмах.
   - **Крок 4, «хто говорить»** (промпт v5: опорні репліки, `=` між сценами, нотатки `@|`, `ч`/`ж`/`x` для людей поза CAST). Виміряно на ручній розмітці мовців (`tools/speakers.py`, 54–67 реплік на фільм):

     | | v4: мовця вгадано / помилки без `?` | v5: мовця вгадано / помилки без `?` | v5: стать мовця правильна |
     |---|---|---|---|
     | Cyberpunk | 85% / 11.9% | 99% / 1.5% | 60/61 |
     | Stranger Things | 86% / 13.6% | 89% / 9.1% | 63/66 |
     | Leon | — | 74% / 14.8% | 46/46 |

     Решта помилок — у сценах, де говорять кілька людей однієї статі (хлопці в піцерії, поплічники Стенсфілда). Для українського перекладу вони майже нешкідливі: рід і ти/ви від них не змінюються. Тому окремого проходу «хто говорить» не робимо; сумнівні сцени покаже `validate`.
   - Найбільша помилка Leon — у глосарії, а не в перекладі: «Stan» записано окремим персонажем, хоча так звуть Стенсфілда. З виправленим глосарієм точність частини зросла з 52% до 74%. У промпт глосарію додано правило про прізвиська; глосарій варто показувати користувачеві перед перекладом.
4. **`validate`**: перевірки, звіт, повторний переклад лише проблемних рядків, статус `refused`.
   - Зроблено: `aisubs validate` (звіт у консоль і `film.aisubs/report.txt`), `aisubs fix` (запит лише з проблемними рядками: попередня відповідь, що не так, сусідні репліки), `import --fix [--next]`. Кожен рядок повертається моделі один раз; якщо й після цього він не проходить перевірку, рядок іде в «To review».
   - На повторний переклад: субтитр читається швидше за 20 CPS або не вміщується у 2 × 42 символи; рядок не перекладено; ім'я з CAST лишилося латиницею; ім'я написано інакше, ніж у глосарії (лише коли в англійському рядку є це ім'я, тож «Бонні» для Bonnie — не помилка); російські літери; зламані теги; залишки формату (`|`, `≤N`, `S>A`); рід дієслова суперечить мовцю чи адресату.
   - На перегляд людиною: позначки `?` про мовця; рядки, що не пройшли перевірку й після повтору.
   - Відмова моделі (жодного прийнятого рядка, текст на кшталт «I can't») — статус `refused` у `status`, порада: новий чат, інша модель або менший `--chunk-size`.
   - Проба на Leon v3 (частини 1–3): 9 рядків на повтор, після одного раунду > 20 CPS — з 1.1% до 0%.
   - `aisubs review`: файл `film.aisubs/review.txt` зі сценами навколо сумнівних рядків (англійський рядок, переклад `частина:ID|S>A|переклад`, нотатки моделі про сцену, коди персонажів). Людина править переклад чи коди, `review --apply` зберігає зміни; виправлені людиною рядки перевірки більше не чіпають і моделі не повертають. Незбережені правки не перезаписуються без `--force`.
   - `prepare` вирізає титри самого файлу субтитрів серед перших і останніх трьох реплік: теги релізу (`HI1`, `720p`, `BluRay`…) або рядок із роком у дужках.
5. **Глосарій**: кандидати кодом, промпт глосарію, рід/число/ти-ви, «стан» між частинами, SDH-метадані, джерела записів; крок веб-пошуку в інструкції; опція `--wikipedia`.
   - Кандидати, промпт глосарію, рід/ти-ви, доповнення `+|` між частинами і SDH-мітки зроблено на етапі 3.
   - `--wikipedia [СТОРІНКА]` для `prepare` і `glossary`: стаття англійською через пошук MediaWiki API («назва рік film» / «TV series» для SxxEyy; береться перший результат, що містить усі слова назви), розділ Cast / Characters, і через міжмовне посилання — розділ «Ролі» / «У ролях» української статті з усталеними українськими іменами. Результат — `film.aisubs/wikipedia.txt`, він іде в запит глосарію. Персонажі, чиїх імен немає в субтитрах, позначаються `[not in the subtitles]`; якщо таких понад 70% — попередження про інший фільм. Без мережі чи при помилці крок пропускається з повідомленням.
   - Після збереження глосарію код попереджає: ім'я з CAST не трапляється в субтитрах; часте ім'я (≥ 5 разів) не потрапило ні в CAST, ні в TERMS (звертання на кшталт Mom, sir не враховуються).
   - Промпт глосарію: правило про прізвиська й короткі імена вже відомих персонажів (Stan = Norman Stansfield); один веб-пошук складу, якщо модель не знає фільму й має пошук.
6. **`guide`** і **адаптер Claude Code**: інструкції для агента з CLI, скіл, `plugin.json`, `marketplace.json`.
   - `aisubs guide [film.srt] [--command …]`: інструкція з `aisubs/prompts/guide.md` з підставленими шляхами й тим способом запуску, яким викликано CLI (`aisubs`, `python -m aisubs` або `python шлях/до/aisubs` — пакет запускається як тека без встановлення). Тест звіряє кожну команду й опцію з інструкції з CLI.
   - Плагін Claude Code: `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` (плагін у корені репозиторію), скіл `skills/translate/SKILL.md` → `/aisubs:translate film.srt [побажання]`. Скіл дозволяє наперед `python3 ${CLAUDE_PLUGIN_ROOT}/aisubs …`, тож користувача не питають про кожен виклик. `claude plugin validate .` — без помилок.
   - Встановлення (коли репозиторій стане публічним): `/plugin marketplace add yar4ick/ai-subtitle-translator-uk`, далі `/plugin install aisubs@aisubs`.
   - Проба: `claude -p --plugin-dir . --model sonnet "/aisubs:translate sintel_en.srt …"` пройшов увесь цикл сам (підготовка, глосарій, переклад, перевірки, fix, review, assemble). Знайдена вада — модель повторювала `≤N` після `S>A` — виправлена в розборі відповіді.
7. **Перевірка з іншими агентами**: Claude Code і Antigravity CLI (наступник Gemini CLI); інструмент для фільмів, яких користувач ще не бачив.
   - Порівняння на Cyberpunk: Edgerunners S01E01 (290 субтитрів), без втручання людини. Claude Code + Sonnet 5.5 (плагін): ~5 хв, 25.5k вихідних токенів, $0.54 за цінами API. Antigravity + Gemini 3.8 Flash (`aisubs guide` у першому повідомленні): ~20 хв, 48.8k вихідних, ~20% тижневої квоти Flash. Мовці правильно в 99% розмічених рядків в обох; ти/ви з людським перекладом: 2 розбіжності в Claude, 0 у Gemini; > 17 CPS: 0.7% і 0%.
   - Вади: Claude помилився з роллю персонажа в глосарії й пом'якшував лайку («Блін!» для «Shit!»); Gemini транслітерував сленг («чум», «Ново!»), читав увесь `.srt` і рахував довжину скриптами, правив відповідь глосарію скриптом.
   - Висновок: людина, яка не бачила фільму, не перевірить ролі й сюжет у глосарії, а показаний їй сюжет — спойлер. Тому глосарій лишається повним для моделі, а людині показується лише рядок `Names:` (імена й рід); агент не чекає підтвердження, якщо користувач не попросив перевірити глосарій. `review.txt` позначається як спойлер.
   - Перевірка роду кодом: займенники he/she після згадки імені (не у звертанні, не в репліці іншого мовця після «-») і Mr/Mrs перед ним; попередження, коли рід у CAST їм суперечить. На трьох фільмах — жодної хибної тривоги, ловить 6 з 32 навмисно перевернутих родів.
   - Промпти: лайка за силою оригіналу зі шкалою прикладів; сленг і звертання — змістом, транслітерація лише для імен, брендів і вигаданих термінів. Інструкція агента: не читати `.srt` і робочі файли, не рахувати довжину, не переказувати сюжет; виправлену відповідь записувати цілим файлом.
   - Antigravity питає дозвіл на кожну нову форму команди й запам'ятовує її в `~/.gemini/antigravity-cli/settings.json`.
8. **Документація** (README українською та англійською з короткою інструкцією для кожного інструмента), **реліз v0.1.0**; репозиторій стає публічним.

## Домовленості

- Репозиторій приватний до v0.1.0.
- Ліцензія MIT.
- README: розділи українською та англійською, коротка інструкція для кожного ШІ-інструмента.
- Файли фільмів `.srt` не комітяться (авторське право); у тестах — відкриті субтитри (після перевірки ліцензії) та власні зразки з `tests/fixtures/`.
- Python ≥ 3.10, лише stdlib.
- Пріоритетна платформа: Claude Code.
- SDH: за замовчуванням прибирається (мітки мовців спершу зберігаються як метадані); `--keep-sdh` зберігає й перекладає.
- Інформація про фільм: знання моделі → необов'язковий веб-пошук через агента → необов'язково Wikipedia через код (`--wikipedia`); усе звіряється з іменами в субтитрах.
- Норми Netflix — орієнтир (попередження), повторний переклад лише при грубих порушеннях.
- Діалог: `-Текст` (дефіс без пробілу).
- Строге 1:1.
