# План: ai-subtitle-translator-uk

ШІ-переклад субтитрів (SRT) з англійської та інших мов на українську.
CLI-команда: `aisubs`.

## Цілі

- **Ощадливість токенів**: модель бачить лише текст реплік, без таймкодів і розмітки.
- **Детермінованість**: усе, що можна зробити кодом, робить код; ШІ лише складає глосарій і перекладає.
- **Незалежність від ШІ-постачальника**: працює з Claude Code, Codex CLI (ChatGPT), Gemini CLI, Cursor та у ручному режимі через веб-чат.

## Архітектура

Ядро — Python CLI **без залежностей** (лише stdlib). Інструкції для ШІ написані один раз у `prompts/` і підключаються до різних інструментів тонкими адаптерами.

| Користувач | Як працює |
|---|---|
| Claude Pro/Max | Плагін Claude Code: `/plugin marketplace add <user>/ai-subtitle-translator-uk`, далі `/translate-subs film.srt` |
| ChatGPT Plus/Pro | Codex CLI читає `AGENTS.md` |
| Gemini, Cursor тощо | Ті самі інструкції з `AGENTS.md` |
| Тільки веб-чат | Ручний режим: `aisubs next` друкує готовий до вставки промпт, `aisubs import` приймає відповідь |
| API-ключ (пізніше) | `--backend anthropic/openai`, необов'язково |

### Робоча папка перекладу

Поруч із фільмом створюється `film.aisubs/`:

- `cues.json` — репліки з таймкодами та плейсхолдерами;
- `candidates.json` — імена/мітки мовців, знайдені кодом;
- `glossary.json` — персонажі, стать, ти/ви, терміни, опис сюжету (редагується вручну);
- `chunks/` — частини для перекладу;
- `done/` — прийняті переклади (повторно ніколи не перекладаються).

Це дає змогу продовжити після ліміту підписки або змінити ШІ посеред фільму.

## Пайплайн

| Етап | Хто | Що |
|---|---|---|
| 1. Розбір SRT → JSON | код | таймкоди й стилі не потрапляють до моделі |
| 2. Теги `<i>`, `{\an8}` → плейсхолдери `⟦1⟧` | код | модель не ламає розмітку |
| 3. Пошук кандидатів у персонажі | код | імена, мітки мовців, звертання + 2–3 приклади |
| 4. Глосарій | ШІ, один раз | стать, ти/ви, терміни, сюжет у 2–3 реченнях |
| 5. Переклад частинами | ШІ | формат `n|переклад`, позначка `?` при сумніві |
| 6. Перевірка | код | id, плейсхолдери, довжина, CPS, позначки `?` |
| 7. Повторний переклад | ШІ | лише рядки, що не пройшли перевірку |
| 8. Збирання `.uk.srt` | код | оригінальні таймкоди, перенесення рядків |

## Визначення статі мовця

У SRT немає інформації про мовця, тому стать **виводиться з непрямих ознак**:

| Джерело | Приклад | Хто аналізує |
|---|---|---|
| Мітки мовців (SDH) | `SOPHIE: Where are you?`, `[Ethan]` | код, точно |
| Звертання за ім'ям | `Thanks, Sophie.` | код знаходить, ШІ робить висновок |
| Слова, що вказують на стать | `I'm a good wife`, `Mr./Mrs.`, `he said` | ШІ |
| Черговість реплік | тире `- ` позначає зміну мовця | код + ШІ |
| Знання про фільм | назва з імені файлу | ШІ, з перевіркою |
| Список персонажів від користувача | `Ethan — ч, Sophie — ж, ти` | найнадійніше |

Правила:

1. Модель отримує вибірку з кандидатами, а не весь фільм.
2. Глосарій можна відредагувати вручну перед перекладом.
3. Якщо форма залежить від роду, а мовець неясний, модель ставить `?` у кінці рядка.
4. `aisubs validate` виводить список таких реплік для перевірки або повторного перекладу з ширшим контекстом.
5. Модель може обирати родово-нейтральні конструкції при сумніві, але без шкоди природності тексту.

100% точності без звуку не буде; мета — не вгадувати мовчки, а позначати сумнівні місця.

## Економія токенів

**Вхід**
- Лише `n|текст` з короткою нумерацією в межах частини.
- Код відкидає репліки без перекладу: `♪`, `[music]`, цифри, порожні.
- Для глосарію — вибірка, не весь фільм.
- Контекст між частинами: 5 останніх реплік попередньої частини (оригінал + переклад) і опис сюжету. Повної історії немає.

**Вихід**
- Лише `n|переклад`, без повторення оригіналу та пояснень. Українська займає помітно більше токенів, ніж англійська, тому вихід особливо важливо тримати коротким.

**Робота агента**
- Одна частина — один цикл: `aisubs next` → агент пише відповідь у файл → `aisubs import`. Агент нічого не досліджує сам.
- Частини по ~150–250 реплік, щоб рідше повторювати інструкції.
- У Claude Code — кожна частина в субагенті з чистим контекстом (інструкції + глосарій + частина). Порівняти з однією сесією на етапі 7.
- Для перекладу достатньо Sonnet.

**Без повторних витрат**
- Прийняті частини в `done/` не перекладаються повторно.
- Повторно перекладаються лише рядки, що не пройшли перевірку.
- Перевірка якості — лише для позначених реплік.

## Етапи

Кожен етап — окрема гілка, коміти, злиття в `main`.

0. **Ініціалізація**: `git init`, приватний репозиторій на GitHub, LICENSE (MIT), `.gitignore`, `PLAN.md`, README-заглушка.
1. **SRT**: читання/запис, кодування (UTF-8, BOM, cp1251), CRLF, тести «прочитав → записав без змін».
2. **`prepare`**: частини з контекстом, плейсхолдери, пошук кандидатів у персонажі, робоча папка.
3. **`validate` + `assemble`**: перевірки, звіт, перенесення рядків, збирання.
4. **Промпти**: глосарій і переклад, строгий формат відповіді.
5. **Адаптер Claude Code**: скіл, команда, `marketplace.json`.
6. **`AGENTS.md` і ручний режим**: `aisubs next` / `aisubs import`.
7. **Перевірка на реальному фільмі** (локально), вимірювання токенів, доопрацювання промптів, вибір розміру частин і режиму (сесія чи субагенти).
8. **Документація, CI (pytest у GitHub Actions), реліз v0.1.0**; репозиторій стає публічним.

Пізніше: режими через API, формати ASS/VTT.
